High-level design

The research graph and its two human steps

A report is one long-lived LangGraph thread. It alternates between working and waiting for you. The checkpointer saves state after every step, so a paused run survives a server restart and can be resumed from the UI.

State design

FieldShapeWhy it is shaped this way
outlineordered list of {id, title, questions, queries}The order of the report. The planner writes search queries here so sections need no extra planning call.
sectionsdict by section id, merge reducerParallel workers each return one entry. A revision returns only the changed ids, so the rest are the same objects as before.
sourcesdict by source id, merge reducerSource id is a hash of the URL, created when the page is fetched. It stays attached to passages and sentences from then on.
todo, editssection ids and per-section instructionsThe unit of work. First run: every id. Revision: one or two.
historyappend-only listOne entry per pass with before and after text. Drives the version history and diff.

Everything in state is plain JSON, so the checkpointer and the report file on disk hold the same shape.

No citation, no claim

The writer only sees numbered passages and must end every sentence with a source number. Then each sentence is checked on its own.

Analysis agent, knowledge base and chat

Analysis: a separate graph, on purpose

  • It only reads a finished report, so a failure here can never damage one.
  • Different trigger: research runs when sections change, analysis when you ask.
  • No human step, so no checkpointer or thread needed.
  • Two branches run in parallel: one LLM call for sentiment and recommendations, and a VADER word-list score per source and section that costs no tokens.
  • A final check drops any recommendation that does not point at a real section, and flags sections where the two sentiment readings disagree.

Knowledge base and chatbot

  • Each section is its own document. Chunks carry report id, section title and the cited URLs.
  • After an edit only sections whose content hash changed are embedded again.
  • A report's chat session filters retrieval to that report.
  • Dense, BM25 or hybrid retrieval, chosen in .env.
  • Below the score threshold the bot answers "I couldn't find that" without calling the LLM.
  • Follow-ups are rewritten into standalone queries using the conversation.

Evaluation

Twelve fixed topics, each with four aspects a good report should cover. Two versions run on the same cached evidence. The judge is Qwen, a different model family from the writer.

v1, the baseline

  • No claim verification: whatever the writer produces is kept
  • Dense retrieval for the chatbot

v2, the full system

  • Sentence-level verification with one rewrite
  • Hybrid retrieval (dense + BM25)

What we learned

  • Verification raised groundedness from 0.55 to 0.74 and took uncited sentences to zero. It costs about twice the time and tokens.
  • Coverage did not drop. Reports got shorter and read slightly better.
  • Even with a strict prompt, the unverified writer left 2.3 sentences per report without a citation. A prompt is not a guardrail.
  • The independent judge still rejects about a quarter of v2's sentences, mostly long sentences joining two facts where the source backs one. Next step: judge every sentence or split compound ones.
  • Chat samples are too small (six answerable questions per version) to rank hybrid against dense retrieval.
  • The eval caught a real bug: the model sometimes writes citations as 【1】, which the parser missed. Fixed, with a test.

Switching providers

LLM_PROVIDER=groq            # groq | google | anthropic | openai
LLM_MODEL=openai/gpt-oss-120b
LLM_FALLBACK_PROVIDER=groq   # used when the main provider errors
LLM_FAST_MODEL=openai/gpt-oss-20b
SEARCH_PROVIDER=ddgs         # ddgs | tavily | wikipedia
EMBEDDING_MODEL=fastembed:BAAI/bge-small-en-v1.5
RETRIEVAL_MODE=hybrid        # dense | bm25 | hybrid
RESEARCH_VERIFY=true

Provider packages are imported in one function. The vector collection is named after the embedding model, so changing the model never mixes vectors of different sizes.
