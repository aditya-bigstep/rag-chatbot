Your ideas, assessed

IdeaVerdictLatency costWhy
A local classification modeldo itAbout 3 ms per message (measured)We already load a local embedding model. Classifying a message is one embedding plus a comparison with a few example sentences per label. A quick probe sorted 5 of 5 messages into greeting, research, edit and unsafe. That is a toy check, not an evaluation. Uses: catch rephrased prompt injection the regex misses, route "make section 3 longer" without an LLM call, and tell a greeting from a research topic.
A hosted prompt-guard modeltry itOne small extra call, not measuredYour Groq key lists llama-prompt-guard-2. It is built for spotting injection and could screen topics and, more usefully, web passages before the writer sees them. Worth a day to measure.
Mood from cursor trackingnot as "mood"None on the LLM. It runs in the browser.Cursor data can show struggle: rapid repeated clicks, clicks on things that do nothing, long hovering without acting. Session analytics tools report signals like these. Reading an emotional state from them is much weaker, needs the user's consent, and has little to act on in a research tool. I could not identify the specific site you had in mind, so I have not recommended a product.
A smaller version of that ideacheap winNoneDetect two or three struggle signals in our own code (three edits to the same section in a row, an edit request that changed nothing, a long idle on the outline) and offer help at that moment. Call it what it is: noticing when someone is stuck.
Skip our own page fetchingbiggest speed winCould remove most of the 8 to 12 sTavily can return page content with the search results. If that content is good enough, the read stage shrinks to almost nothing. Not yet tested: check that the text is complete enough for the verifier before switching.

What three developers should focus on

Split by what each person can own end to end. The first item in each lane is the one to start on.

Developer A

Trust and evaluation

  1. Re-run the 12-topic evaluation on the Gemini setup. The published numbers are from the old Groq setup.
  2. Find out why the verifier removed nothing on Gemini runs. Either the drafts are cleaner or the judge is softer.
  3. Judge every sentence, or split long ones first. The independent judge still rejected about 30% of sentences.
  4. Write score_source. Every source shows "trust 50%" until it exists.
  5. Capture the LangSmith traces and dashboard for the deliverables.

Developer B

Experience

  1. Stream section text into the page while it is written.
  2. Replace the browser prompt and confirm boxes (rewrite, remove, delete) with in-page dialogs.
  3. Add the local classifier and use it for the stuck-user help.
  4. PDF export, and a side-by-side view of two topics.
  5. Test the welcome page on real phones. It has only been checked in a desktop browser at phone size.

Developer C

Platform and speed

  1. Test Tavily page content in place of our own fetching.
  2. Per-user limits: reports per day and LLM calls per day, so one account cannot spend the free quota.
  3. Send one real sign-up and one reset e-mail end to end and check they arrive and are not marked as spam.
  4. Move runs from an in-process thread pool to a job queue, so a restart does not interrupt them.
  5. Deployment: one command to run it, HTTPS, and secrets outside the repo.
